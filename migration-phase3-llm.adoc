==== Prompt 3.1: NoteMapper Interface generieren

**Kontext-Dateien:**
- `src/main/java/com/gepardec/notizblock/entity/Note.java`
- `src/main/java/com/gepardec/notizblock/dto/NoteDTO.java`

**Prompt:**

[source,text]
----
Erstelle ein MapStruct Mapper-Interface für die Konvertierung zwischen Note Entity und NoteDTO.

Kontext-Dateien:
- Note.java (Entity)
- NoteDTO.java (DTO)

Anforderungen:
1. Package: com.gepardec.notizblock.mapper
2. Interface-Name: NoteMapper
3. MapStruct Annotation: @Mapper(componentModel = "cdi")
4. Methoden:
   - NoteDTO toDTO(Note entity)
   - Note toEntity(NoteDTO dto)
   - List<NoteDTO> toDTOList(List<Note> entities)
   - List<Note> toEntityList(List<NoteDTO> dtos)
5. Alle Felder haben gleiche Namen → automatisches Mapping
6. Keine @Mapping Annotations nötig (Feldnamen stimmen überein)

Hinweise:
- componentModel = "cdi" für Quarkus CDI Integration
- MapStruct generiert Implementierung zur Compile-Time
- Verwendung: @Inject NoteMapper in REST Resource
----

=== Schritt 4: REST Resource implementieren

==== Prompt 4.1: NoteResource generieren

**Kontext-Dateien:**
- `src/main/java/com/gepardec/notizblock/bean/NoteBean.java`
- `src/main/java/com/gepardec/notizblock/repository/NoteRepository.java`
- `src/main/java/com/gepardec/notizblock/dto/NoteDTO.java`
- `src/main/java/com/gepardec/notizblock/mapper/NoteMapper.java`

**Prompt:**

[source,text]
----
Konvertiere den folgenden JSF Backing Bean zu einer JAX-RS REST Resource.

Kontext-Dateien:
- NoteBean.java (JSF Bean mit CRUD-Logik)
- NoteRepository.java (Data Access)
- NoteDTO.java (DTO)
- NoteMapper.java (MapStruct Mapper)

Anforderungen:
1. Package: com.gepardec.notizblock.resource
2. Klassenname: NoteResource
3. JAX-RS Annotations:
   - @Path("/api/notes")
   - @Produces(MediaType.APPLICATION_JSON)
   - @Consumes(MediaType.APPLICATION_JSON)
4. Dependency Injection:
   - @Inject NoteRepository noteRepository
   - @Inject NoteMapper noteMapper
5. Endpoints (basierend auf NoteBean Methoden):

   a) GET /api/notes - Liste aller Notizen
      - Ruft noteRepository.findAll()
      - Konvertiert mit noteMapper.toDTOList()
      - Return: List<NoteDTO>

   b) GET /api/notes/{id} - Eine Notiz abrufen
      - @PathParam("id") Long id
      - Ruft noteRepository.findById(id)
      - Wenn nicht gefunden: Response.status(404)
      - Wenn gefunden: Response.ok(noteMapper.toDTO(note))

   c) POST /api/notes - Neue Notiz erstellen
      - Body: NoteDTO (ohne id)
      - Konvertiert mit noteMapper.toEntity()
      - Ruft noteRepository.create()
      - Return: Response.status(201).entity(noteMapper.toDTO(created))

   d) PUT /api/notes/{id} - Notiz aktualisieren
      - @PathParam("id") Long id
      - Body: NoteDTO
      - Prüft ob Notiz existiert (404 wenn nicht)
      - Setzt id vom Path-Parameter
      - Ruft noteRepository.update()
      - Return: Response.ok(noteMapper.toDTO(updated))

   e) DELETE /api/notes/{id} - Notiz löschen
      - @PathParam("id") Long id
      - Ruft noteRepository.delete(id)
      - Return: Response.noContent() (204)

6. Error Handling:
   - Try-Catch für alle Methoden
   - Bei Fehler: Response.status(500).entity(new ErrorResponse(...))

7. Keine @Transactional nötig (Repository hat bereits @Transactional)

Hinweise:
- Verwende Optional.orElseThrow() für 404 Handling
- Alle Responses als Response-Objekt für flexible Status-Codes
- DTO statt Entity verwenden (nie Entities direkt zurückgeben)
----

**Generierter Code:** (siehe NoteResource.java)

=== Schritt 6: OpenAPI Annotations hinzufügen

==== Prompt 6.1: OpenAPI Annotations für NoteResource

**Prompt:**

[source,text]
----
Füge OpenAPI/Swagger Annotations zur NoteResource Klasse hinzu.

Anforderungen:
1. Klassen-Level:
   - @Tag(name = "Notes", description = "Notizen-Verwaltung API")

2. Methoden-Level (für jeden Endpoint):

   GET /api/notes:
   - @Operation(summary = "Alle Notizen abrufen")
   - @APIResponse(responseCode = "200", description = "Erfolg")

   GET /api/notes/{id}:
   - @Operation(summary = "Eine Notiz abrufen")
   - @APIResponse(responseCode = "200", description = "Notiz gefunden")
   - @APIResponse(responseCode = "404", description = "Notiz nicht gefunden")

   POST /api/notes:
   - @Operation(summary = "Neue Notiz erstellen")
   - @APIResponse(responseCode = "201", description = "Notiz erstellt")
   - @APIResponse(responseCode = "400", description = "Ungültige Eingabe")

   PUT /api/notes/{id}:
   - @Operation(summary = "Notiz aktualisieren")
   - @APIResponse(responseCode = "200", description = "Notiz aktualisiert")
   - @APIResponse(responseCode = "404", description = "Notiz nicht gefunden")

   DELETE /api/notes/{id}:
   - @Operation(summary = "Notiz löschen")
   - @APIResponse(responseCode = "204", description = "Notiz gelöscht")

3. Parameter-Annotations:
   - @Parameter(description = "Notiz-ID") für Path-Parameter

Hinweise:
- Import: org.eclipse.microprofile.openapi.annotations.*

== Lessons Learned

=== Was funktioniert gut mit LLM:

1. ✅ DTO-Generierung aus Entities
2. ✅ MapStruct Interface-Definitionen
3. ✅ REST Resource Struktur (aus Backing Beans)
4. ✅ Exception Handling Boilerplate
5. ✅ OpenAPI Annotations
6. ✅ Basis-Tests mit REST Assured

=== Was manuelles Review braucht:

1. ⚠️ Business-Logik Validierung
2. ⚠️ Error Handling Edge Cases
3. ⚠️ Performance-Optimierung (N+1 Queries)
4. ⚠️ Security (Authentication/Authorization)
5. ⚠️ Projekt-spezifische Validierung

=== Optimierungen:

1. **MapStruct** reduziert Mapping-Code signifikant
2. **Quarkus Dev Mode** ermöglicht Hot-Reload
3. **OpenAPI** generiert automatisch API-Dokumentation
4. **REST Assured** vereinfacht Testing
